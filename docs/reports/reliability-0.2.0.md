# 0.2.0 可靠性验证

日期：2026-10-17。环境：macOS arm64，Tern 0.9.0，Pi 1.2.0。范围为本地桌面插件、Pi 状态桥、安装器和发布包。

## 自动测试

- 46 个真实 Luau 模块/运行时边界测试通过。
- 9 个 Pi 状态桥生命周期与隐私测试通过。
- 13 个 Python 安装器/打包测试通过，包括预检失败、更新中断、后续状态查询失败、卸载失败回滚、回滚再次失败时原地保留唯一备份、未知文件/符号链接保护、禁止私有路径进入包。
- GitHub CI 分别运行 Node 22 与 Node 24 的便携测试；CI 结果由仓库 Actions 记录，不将其当作原生窗口验证。

新增回归先在旧实现失败，再分别修复：临时缺报告后保留同轮已读、Native 取消等待不制造结果、原生重复完成不覆盖已读、窗口/Host 刷新异常后继续调度、启动 KV 异常恢复、完成与离焦之间的采样窗口、双 Window VM 合并已读。

## 原生验收

完整运行：`python3 scripts/verify_native.py --out artifacts/native/reliability-002 --pi-dialog-rounds 3`。补充边界重试与回滚复审修正后，以相同参数复跑到 `artifacts/native/reliability-003/`；最终结果和源码哈希以后一份 summary/manifest 为准。

结果：**24 项通过，运行错误列表为空**。证据包含 summary、PNG、原生布局、独立数字字形对照、独立配置、源码拷贝与测试进程退出记录。测试不调用外部模型，也不修改日常 Tern 配置。

核心覆盖：

- 工作蓝点、等待空心琥珀点、手动配色和同色扫光、hover、水平/垂直标签、深浅色主题。
- 实际数字 4、3、1 的字形对照，全部已读后恢复小绿点；标题几何稳定。
- 重载、暂停、恢复、下一轮重新计数、图标紫色角标移除、卸载恢复原生样式。
- 普通 shell 中真实 Pi 的工作/最终完成，三轮阻塞提问和取消后恢复已读。
- 状态桥文件暂缺后，同一轮次仍保持已读。
- 完成后立即离焦，直接读取原 pane 状态并确认已读。
- Native 空闲对话框取消，不产生完成或新未读。
- 两个真实桌面窗口分别拥有 Agent panes：一个窗口的保存、已读及重载不会覆盖另一个窗口的状态。

## 双窗口范围

Tern 的两个本地桌面窗口在本次环境中拥有不同会话集合，不能把给另一个窗口的 pane ID 调用 focus 当成成功显示。因此真实双窗口测试验证**互不覆盖**，而“同一 pane/同一轮次的已读回执在两个 Runtime 中合并”由共享 KV 的运行时测试验证。未把后者描述成已经完成真实桌面同 pane 镜像验收；远程和浏览器镜像不在本轮范围。

第一次 `reliability-001` 在双窗口测试处失败，因为测试错误地假设新窗口会显示主窗口的标签。该失败被保留；修正驱动使用各窗口真实存在的 panes 后，从干净配置完成 `reliability-002`，不是绕过产品功能断言。

## 独立复审与补充修正

独立只读审查发现：回滚再次失败后若再复制备份，复制失败可能清掉唯一旧备份。新增测试重现后，改为直接原地保留事务目录，不再依赖另一次成功复制才能保存备份。

焦点边界读取一次失败的回归也已补充：测试边界现在返回与 Tern 一样的新快照，而不是复用同一表，防止测试副作用制造假通过。单次读取失败会在同一边界内有界重试；连续失败会显式提示无法确认，并保守保留未读，而不是事后猜测用户是否看过。

## 剩余边界

- Tern 的原生 Agent API 没有真实轮次 ID。完全短于采样间隔、未观察到工作态的 Native 轮次，无法获得与 Pi 桥相同的精度；不使用闲置/等待取消猜测成功。
- `pcall` 处理普通读取异常，但不能恢复 Tern 因 wall-clock 预算超限而禁用的钩子；需要原生宿主诊断与必要时重载。
- CSS 依赖 Tern 0.9 的标签结构，宿主改版后必须复验。
- 本次没有增加 Claude/Codex 等普通终端的专用状态桥，也不宣称支持其未上报状态。

当前源码与被测拷贝的哈希、实际本机安装回读、未改变原生偏好的检查在交付时写入本地 `artifacts/production/`。测试运行目录和个人配置不会提交到公开仓库。
