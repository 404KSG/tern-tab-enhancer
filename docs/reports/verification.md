## 工作中标题颜色修正

用户指出紫色、蓝色 Tab 的标题在工作中变成灰白。实际元数据确认这两行有原生 `working` 动画，原生样式以透明文字和灰白背景渐变实现扫光，覆盖了手动文字颜色。修复仅覆写带 `data-tc` 的工作标题渐变，用手动颜色的 80%—100% 明暗替代灰白，不改动画名称、时长或减少动态效果偏好。

新增回归测试在修复前失败。原生截图中，旧实现检测到 219 个灰白文字像素、0 个手动颜色像素；修复后为 0 个灰白像素、436 个手动颜色像素，且 `stats` 仍报告原生标题动画。新增原生场景是 `working-title-follows-manual-hue`，运行证据位于 `artifacts/native/title-hue-001/`；源码哈希以该次运行的 `runtime-hashes.json` 为准。

## 历史尝试与范围

- `acceptance-001` 的 hover 测试因控制命令的 CSS 选择器未加场景字符串引号而失败；修正测试驱动后，002 的 15 个早期原生场景通过。
- 003 在 Pi 提问转换处出现一次等待超时；004 的完整 17 场景通过。005 的后台窗口 hover 采样没有看到目标绘制状态，因此没有判为通过。
- 最终驱动在等待时推进其独立窗口的控制帧，并等待真正的 hover 绘制，替代固定 250ms 的假设；006 从干净配置完整通过，并重复 Pi 提问恢复三轮。旧失败不计入最终通过结果。

- 正式窗口曾在旧同步启动入口遇到一次 `load exceeded 50 ms`。探针记录模块加载、编译及 KV 读取的调用链；热重载时合计约 5.2ms，但冷路径不能据此保证。最终入口不进行模块 I/O 或 KV 读取，等待窗口生命周期并分段加载；测试断言冷启动入口没有上述同步操作。
- 007–009 的隔离窗口没有创建初始 pane。无插件对照在账号门禁恢复后同样出现空 pane，额外新建标签后立即正常；010 的测试流程先等待已有账号门禁完成，再在自己的隔离窗口显式创建测试标签，无需重启或更改日常窗口。
- 当前展示层移除图标旧 `::before` 扫光，避免图标改为静态定位后扫光错误铺满整个标签；Tern 原生标题扫光和全局动画偏好不变。
